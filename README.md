# reverse-report-editor

用于精修已有技术与业务分析资料的 Codex skill，界面名称为「分析文档精修」。在保留原有结构、事实、技术细节和证据强度的基础上，改善措辞、术语一致性、指代及段落衔接。

虽然项目名称含有 `reverse`，其适用范围不限于逆向报告，也包括架构说明、协议笔记、性能报告和业务规则分析。

## 适用场景

- 整理已有分析报告、专题说明和研究笔记，让表达更清楚、连贯。
- 精修技术机制与业务流程说明，准确区分触发条件、处理行为和完成状态。
- 在指定文件或目录范围内统一术语与表达，保留各文档原有用途。
- 仅审阅材料，指出表达问题、实质歧义和待确认事项。

本 skill 面向已有材料的编辑，不代替原始研究、事实核验或从零生成新分析，也不会因润色任务自行开展实验、抓包或技术验证。

## 默认编辑方式

默认保留文件名、标题及层级、章节顺序、表格结构和导航链接，主要在句段内改善表达。代码、伪代码、技术标识、数值、引用与原始数据保持准确；用户明确要求重组或面向新读者改写时，再按指定幅度调整。

文风按以下优先级确定：

1. 当前任务的明确要求。
2. 用户指定的风格样本。
3. 当前资料中稳定的文风约定。
4. 默认的**技术业务说明风格**。

没有可沿用的文风时，使用客观、准确、适度正式的书面语，讲清材料已有的技术机制、业务条件和处理结果。默认风格不要求套用固定章节，也不补写未经确认的业务目的、收益或因果关系。

原稿中的事实、推断、未知和验证限制分别保留。例如，“任务已提交”不能改成“业务已完成”，“单个样本中观察到”不能改成“系统始终如此”。

## 使用示例

在 skill 已可用的环境中，可通过 `$reverse-report-editor` 指定使用，并提供待编辑材料或文件路径。以下路径为示例，使用时替换为实际目标。

**精修并写回文件：**

```text
使用 $reverse-report-editor 精修 docs/analysis.md 并写回。
保留现有结构、技术细节和证据边界；没有既定文风时，按技术业务说明风格处理。
```

**参考指定文风：**

```text
使用 $reverse-report-editor 精修 docs/business-flow.md 并写回，
参考 docs/style-sample.md 的表达习惯。样本只用于文风参考。
```

**仅审阅：**

```text
使用 $reverse-report-editor 审阅 docs/report.md，不修改文件。
指出措辞、术语、指代及段落衔接问题，并列出无法凭现有材料解决的疑点。
```

也可以直接指定本项目的 `SKILL.md` 路径，要求读取并按其中规则处理材料。目录级任务应说明编辑范围；有目标读者、风格样本或重组要求时，一并提供。

## 交付与检查

要求精修文件时，在指定范围内写回，并简要说明改动、实际执行的检查及未解决的问题；仅审阅时交付问题与建议，用户只要正文时只交付正文。

检查包括与原文对照结构、链接、代码、数值和引用，以及复核主体、条件、时序、否定和证据强度。文档格式检查不等于技术事实验证。
